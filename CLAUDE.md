## Project Overview

ToolkitFree is a free, local-first browser tools website. The core product promise is:

> Your files never leave your device.

Selected file contents are processed in the browser with Canvas, WebAssembly, or client-side
JavaScript. Be precise: pages still load normal site resources, Background Remover downloads model
assets, and video conversion loads a site-hosted FFmpeg runtime when needed.

Current public tools:

- Image Converter
- Image Compressor
- Image Resizer
- Image Enhancer
- Image Collage Maker
- Image Splitter
- ID Photo Size & Print Tool
- Image Cropper
- Background Remover
- Video to GIF, WebP & APNG
- Image to PDF
- PDF Splitter & Page Extractor
- Favicon Generator
- QR Code Generator

Advertising is intentionally disabled while product quality and user experience are improved. Do
not reintroduce advertising scripts or placeholders without the project owner's approval.

## Package Manager and Commands

Use npm and preserve `package-lock.json`.

- `npm run dev` — start the Astro development server
- `npm run build` — build the static site to `dist/`
- `npm run preview` — preview the production build
- `npm run typecheck` — TypeScript validation
- `npm run lint` — ESLint with zero warnings
- `npm run format:check` — Prettier validation
- `npm run test` — unit and algorithm validations
- `npm run check` — full local quality gate
- `npm run test:e2e` — full Chrome browser regression
- `npm run test:e2e:edge` — Edge smoke regression

## Architecture

- Astro renders static pages.
- React components provide interactive tool islands with `client:load`.
- `src/data/tool-registry.ts` is the single source for public tools, navigation, related tools,
  sitemap entries, and machine-readable registries.
- `src/data/guide-registry.ts` is the single source for guide metadata and guide/tool relationships.
- `src/lib/` contains shared processing, resource budgets, export helpers, and pure algorithms.
- `ObjectUrlRegistry` and `useObjectUrlRegistry` manage temporary object URLs.
- Shared helpers such as `formatSize` live in `src/lib/image-processing.ts`; do not duplicate them.
- Deployment targets Cloudflare Workers static assets through Wrangler.

## Working Rules

- Inspect the branch and working tree before implementation.
- Fetch and pull remote changes before new repository work.
- Read `PROJECT_STATUS.md` before planning or implementation, and update it in the same change after
  every completed feature, important decision, release step, deployment, or meaningful validation.
  It is the living handoff; do not create routine one-off handoff files.
- Preserve unrelated user changes.
- Do not push unless the project owner asks.
- Run checks proportional to the change; meaningful UI work requires browser regression.
- Check for existing preview or browser-test processes before starting another service.

## Product and Content Rules

- Do not claim complete privacy, zero network requests, unlimited input size, guaranteed compression
  savings, guaranteed exact target size, or support that has not been implemented and verified.
- Keep public tool metadata, sitemap coverage, navigation, related links, `llms.txt`, and
  `llms-full.txt` synchronized through their registries and validation scripts.
- When adding, renaming, or removing a public page, follow the checklist in `AGENTS.md`
  ("Checklist: Adding a Tool or Variant Page") before running the gates. `llms.txt` and
  `llms-full.txt` are generated by `npm run sync:llms`; never hand-edit their generated
  sections. `validate-seo-registry.mjs` fails if any indexable route is missing from them.
- Programmatic variant pages must provide real intent-specific value and accurate capability copy.
- Prefer useful specifications and limitations over repetitive FAQ content.
- The global English-speaking audience remains the initial target.
